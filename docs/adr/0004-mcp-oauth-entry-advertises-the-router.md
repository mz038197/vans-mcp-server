# A second entry, /mcp-oauth, advertises the router as authorization server

`/mcp` deliberately answers a missing or refused key with a plain 401 and no `WWW-Authenticate`, because VS Code and Cursor otherwise start OAuth Dynamic Client Registration and ignore the configured `Authorization: Bearer vcr_sk_…` header. MiTAC Agent Builder, used by a whole class in one shared space, links each student through "OAuth 2.0 (user authorization)" against the router (router ADR 0094), and it may only start that link when the server challenges. So the same MCP app is also mounted at `/mcp-oauth`, whose 401 carries `WWW-Authenticate: Bearer resource_metadata=…` pointing at `/.well-known/oauth-protected-resource/mcp-oauth` (RFC 9728), which names the router as the authorization server. Authentication is identical on both entries: the token the router issues is the student's Classroom API Key, checked through the Key Check. `/mcp` is unchanged.

Considered: advertise on `/mcp` (breaks VS Code and Cursor static keys); a separate deployment for Agent Builder (two services to keep in step for one header); vans as its own authorization server (copies the router's Invite Code redeem); wait for an Agent Builder test before adding it (kept as insurance; remove it if the platform links users without a challenge).
